模块以 `main.go` 为入口，通过 `wails.Run` 启动 Wails v2 应用，使用 `//go:embed all:frontend/dist` 将 Vite 构建产物内嵌到二进制中；`wails.json` 声明前端安装/构建命令及开发时 dev server URL。

- 顶层 `package main` 承载 Wails 绑定层：`App` 结构体在 `app.go` 中定义，所有大写方法（如 `GetTunnels`、`ConnectServer`、`ApplyVirtualNetwork`）由 Wails 自动暴露给前端 TypeScript 类型（位于 `frontend/wailsjs/go/main/App.*`），形成 Go→JS 的双向调用边界。
- 业务逻辑按能力拆入 `internal/<pkg>` 子包，依赖方向单向向下：`app.go` → `internal/tunnel`（隧道生命周期）、`internal/p2p`（WebRTC ICE/P2P/TUN）、`internal/config`（SQLite 持久化）、`internal/virtualnet`（虚拟网络路由）、`internal/nat`（STUN 探测）、`internal/probe`（带宽/丢包/RTT 探测）、`internal/quic`、`internal/relay`、`internal/scheduler`、`internal/auth`、`internal/migration`、`internal/oidc`。
- 本地控制面通过 `control_server.go` 启动仅监听 `127.0.0.1` 的 HTTP JSON API，凭据写入 `desktop-control.json` 文件供 CLI 读取，实现进程外控制。
- 平台差异通过 Go build tag 文件组织：`autostart_*.go`、`wintun_repair_*.go`、`internal/p2p/preflight_*.go`、`tun_*.go` 等，共享同一 package 名。
- 独立可执行工具位于 `cmd/`：`p2p-tun-verify` 和 `tun-verify` 用于 TUN 设备验证，不依赖 Wails。
- 前端位于 `frontend/`，Vue3 + TypeScript + Vite，通过 `wailsjs/runtime` 与 Go 侧交互。
