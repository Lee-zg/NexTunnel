模块以 Go 单仓库形式组织，`go.mod` 声明 module `github.com/nextunnel/server`，并通过 `replace github.com/nextunnel/pkg => ../pkg` 复用共享协议与 TLS 工具。

- 进程边界：`cmd/` 下每个子目录是一个独立可执行入口（control-plane、relay、dashboard、ebpf-verify、edge-rehearsal、nat-detector），每个入口仅负责解析命令行参数、构造配置、启动对应 `internal/*` 中的 Server 并处理优雅关闭。
- 内部包分层（`internal/`）：
  - `controlplane`：基于标准库 `net/http` 暴露 `/api/v1/*` RESTful 接口，通过 mTLS CN 或 Bearer Token 鉴权；依赖 `Store` 抽象（内存/SQLite）持久化节点注册表、ACL 规则与密钥交换状态，并提供可选的虚拟网络 IPAM/TUN 管理。
  - `relay`：自定义二进制协议（`TypeAuth`/`TypeWorkConn`）+ QUIC 双通道，维护客户端连接、Proxy 会话与 Mesh 拓扑，提供独立的 Admin HTTP API；支持 mTLS 与可选统计周期打印。
  - `dashboard`：Web 仪表盘后端，中间件链为 CORS → SecurityHeaders → RBAC → Auth → Routes，静态资源由 Vite 构建产物 `web/dist` 提供，用户/审计日志落盘 SQLite，并可反向代理 Relay Admin API。
  - `anycast`：基于 MaxMind GeoIP 的任意路由选择器，供 edge 组件使用。
  - `edge`：边缘节点侧逻辑（注册到 control-plane、健康检查、部署脚本生成）。
  - `natdetect`：STUN/TURN 探测服务器，用于发现 NAT 类型。
  - `sdwan`：策略分类器、QoS 与策略引擎，被 edge/relay 组合使用。
  - `ebpf`：Linux 专用 XDP/eBPF 转发器与内核规则加载器（含 C 源码 `xdp_forwarder.c`，通过 `//go:build linux` 条件编译）。
- 依赖方向：`cmd/*` → `internal/*`，`internal/*` 之间按职责单向引用（如 dashboard 调用 relay admin client、edge 调用 control-plane client），不反向依赖 cmd。
- 存储抽象：controlplane 与 dashboard 均通过接口（`Store` / `DashboardStore`）解耦实现，默认内存 + SQLite 双后端，通过工厂函数按配置选择。
