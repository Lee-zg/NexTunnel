模块以独立 Go module `github.com/nextunnel/pkg` 形式发布，仅依赖 `golang.org/x/crypto`，被上层 client/server 双向引用。

- `protocol/`：控制通道 wire 协议定义。`message.go` 集中声明所有 `MsgType` 常量与 JSON payload 结构体，并通过 `New*Message` 工厂 + `marshalMessage` 统一序列化；`codec.go` 实现 1 字节 type + 4 字节 big-endian length 的帧格式（最大 16MB），并提供线程安全的 `Conn` 封装；`errors.go` 暴露 `ErrPayloadTooLarge`、`ErrConnClosed`、`ErrUnknownMsgType` 等错误类型。消息族按演进阶段分组注释（Phase 2 P2P/Mesh、Phase 3 智能调度）。
- `types/`：纯数据契约包，定义 `ProxyType`、`ProxyStatus`、`TunnelConfig`、`ProxyInfo`、`ClientInfo` 以及 Phase 3 的 `PathType`、`LinkMetricsSnapshot`、`RelayNodeInfo`，供 client/server 共享。
- `tlsutil/`：mTLS 工具集，提供 `LoadServerTLS` / `LoadClientTLS`（强制 TLS1.3）、自签 CA 与证书签发、PEM 文件写入，用于节点间认证。
- `audit/`：结构化审计日志抽象。定义 `AuditLogger` 接口与 `AuditEvent`/`AuditFilter`，并给出三种实现：JSON Lines 文件 (`JSONFileAuditLogger`)、SQLite 持久化 (`SQLiteAuditLogger`)、空实现 (`NopAuditLogger`)，通过组合注入到上层。
- `ipam/`：IPv4 CIDR 地址分配器，基于 `Allocator` 接口由 `IPAM` 实现，使用 uint32 偏移扫描避免 network/broadcast/gateway 冲突，支持 `Reserve` 恢复持久化状态。
- `crypto/`：密钥生成与加解密工具（见 `keys.go`）。
- `route.go`（位于 ipam 下）：与 IPAM 配套的虚拟路由管理。

依赖方向：`protocol` 与 `types` 无内部依赖；`tlsutil`、`audit`、`ipam`、`crypto` 仅依赖标准库与 `x/crypto`；上层业务组件反向依赖本模块，本模块不依赖任何业务逻辑。
